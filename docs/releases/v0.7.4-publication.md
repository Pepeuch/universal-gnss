## 3. Create and push stable tag only with explicit approval

Verify v0.7.4 is still absent and remote main is exactly the approved green SHA.
Record that SHA as `UG_RELEASE_SHA` (not a placeholder to execute blindly).
Approval must distinguish local tag creation from pushing the tag: tag push
**automatically publishes images** through `docker-release.yml`.

```bash
git tag -a v0.7.4 "$UG_RELEASE_SHA" -m 'Universal GNSS v0.7.4 stable'
git rev-parse 'v0.7.4^{commit}'
# Execute only when tag push AND automatic image publication are approved:
git push https://github.com/Pepeuch/universal-gnss.git refs/tags/v0.7.4
```

Never move an existing published tag. The publishing workflow does not wait for
other CI workflows; the prior exact-main-SHA gate is mandatory. Do not launch
`workflow_dispatch` with `publish=true` without the same publication approval.

## 4. Verify published artifacts

The unchanged workflow builds Kilted and Lyrical, each on linux/amd64 and
linux/arm64, with OCI version/revision labels, `sbom: true` and
`provenance: mode=max`. It checks index platforms and a nonempty output digest.
It does not itself independently inspect SBOM contents, subject binding or
provenance materials. BuildKit attestations do not by themselves establish a
separate signed GitHub artifact attestation.

After approved publication, save authenticated inspection output outside Git,
then record only compact identities/results in docs/validation and shared:

```bash
for UG_DISTRO in kilted lyrical; do
  UG_IMAGE="ghcr.io/pepeuch/universal-gnss-ros2-${UG_DISTRO}:v0.7.4"
  docker buildx imagetools inspect "$UG_IMAGE"
  docker buildx imagetools inspect "$UG_IMAGE" --format '{{json .Manifest}}'
  docker buildx imagetools inspect "$UG_IMAGE" --format '{{json .Provenance}}'
  docker buildx imagetools inspect "$UG_IMAGE" --format '{{json .SBOM}}'
done
```

Record both immutable index digests and all four runtime platform manifest
digests, distinguishing attestation manifests from runtime manifests. Reinspect
using image@sha256 references. Verify both expected platforms, OCI version
v0.7.4/revision approved SHA, each platform's SBOM inventory and provenance
subject/materials/parameters binding. Review resolved base and dependency
identities; floating base images/apt can differ from rc6 despite unchanged code.
Missing or mismatched payloads are a publication qualification failure.
Run the documented Docker smoke/startup checks on the stable digests for both
ROS distributions/platforms, stating native versus emulated coverage. No
production replacement or hardware action is authorized by these instructions.

Anonymous rc6 GHCR inspection returned HTTP 403 in this environment; stored
payload verification is pending authenticated access, not a claimed PASS.
See [Docker attestation guidance](https://docs.docker.com/build/ci/github-actions/attestations/)
and [imagetools inspection reference](https://docs.docker.com/reference/cli/docker/buildx/imagetools/inspect/).
