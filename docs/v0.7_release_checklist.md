# v0.7 Docker release checklist

This is a release-review aid, not evidence that an unchecked item is accepted.
`TODO.md` remains the authoritative v0.7 accounting source.

## Proven release baseline

- [x] Kilted amd64 production image build/runtime evidence
- [x] Lyrical amd64 production image build/runtime evidence
- [x] Kilted/Lyrical arm64 BuildKit/QEMU packaging and smoke evidence
- [x] stable-by-id, non-root, no-privileged serial-device policy
- [x] external NTRIP configuration with credentials outside the image
- [x] tini/entrypoint graceful shutdown contract
- [x] conservative USB-loss/recreate/re-resolve/reprovision contract
- [x] same-host Docker bridge DDS and domain-isolation evidence
- [x] standard OCI image identity and runtime diagnostic identity
- [x] immutable-tag rollback guidance and SBOM/provenance release-artifact plan
- [x] local non-secret support snapshot tool

## Required before release acceptance

- [ ] Native arm64 runtime and receiver/caster evidence (QEMU is not native)
- [ ] External-LAN DDS acceptance using independent LAN peers
- [ ] Receiver/process/container incarnation and restart matrix
- [ ] Serial renumbering, receiver swap, and persistence matrix
- [ ] Long-duration, host-reboot, rate-mismatch, and RTK Fixed evidence
- [ ] Image publication and multi-architecture publish pipeline authorization

## Operator and validation notes

- Docker health is process-only. Use ROS diagnostics/snapshot for transport,
  observation freshness, fix, NTRIP, RTCM, correction semantics, and RTK.
- The workspace sandbox can prevent Fast DDS/NTRIP sockets with `Operation not
  permitted`; that is not a production NTRIP failure and must not be fixed by
  changing runtime networking code.
- Do not attach a transient tty, mount broad `/dev`, use `--privileged`, claim
  hotplug recovery, or silently substitute a receiver.
- The external-LAN gate remains blocked until machine A runs the default-bridge
  container and independent machine B proves both directions plus domain
  isolation. Host networking is not a substitute.
