# v0.7 Docker release checklist

This is a release-review aid, not a second source of backlog truth. `TODO.md`
owns release accounting; each state below names the evidence boundary.

## PROVEN

- Kilted amd64 and Lyrical amd64 production build/runtime contracts.
- Kilted/Lyrical arm64 BuildKit/QEMU packaging and smoke (emulated only).
- Stable by-id, non-root, no-privileged serial-device policy.
- External NTRIP configuration and credentials outside the image.
- tini entrypoint, `SIGINT` stop contract, and process-only Docker healthcheck.
- Standard OCI identity, runtime diagnostic identity, immutable-tag rollback,
  and SBOM/provenance release-artifact plan.
- Same-host Docker bridge DDS/domain-isolation evidence.
- Local non-secret support snapshot tool, external logs, and bounded retention
  guidance.

## PARTIAL

- USB-loss contract: selected stable identity must be re-resolved and the
  container recreated; UM982 runtime-only profile must be replayed after power
  loss. This is not transparent hotplug recovery.
- Bounded no-device lifecycle: both node processes stayed alive and Docker
  process health was healthy while receiver discovery and NTRIP reported their
  own degraded states. Unreadable config exits 1, unsupported schema exits 2,
  and clean SIGINT stop exits 0.
- Live u-blox/Unicore GNSS, NTRIP, RTCM, and RTK Float evidence. RTK Fixed and
  the complete receiver/NTRIP/restart matrix remain separate.

## BLOCKED

- Native arm64 runtime and receiver/caster acceptance: QEMU is not native.
- External-LAN DDS: requires independent physical/routed LAN peers for both
  directions and domain isolation; default bridge is the first test mode.
- The workspace sandbox can prevent Fast DDS/NTRIP sockets with `Operation not
  permitted`; this is not a production NTRIP failure and must not drive runtime
  networking changes.

## PENDING

- Receiver/process/container incarnation and restart matrix.
- Serial renumbering, receiver swap, and persistent-profile matrix.
- Long-duration, host-reboot, rate-mismatch, and RTK Fixed evidence.
- Multi-architecture publication pipeline and publication authorization.

## Operator limits

- Docker health is process-only. Use ROS diagnostics/snapshot for transport,
  freshness, fix, NTRIP, RTCM, correction semantics, and RTK.
- Never attach a transient tty, mount broad `/dev`, use `--privileged`, claim
  automatic hotplug recovery, or silently substitute a receiver.
